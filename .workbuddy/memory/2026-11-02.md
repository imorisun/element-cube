# 2026-11-02

## 修复：打开元素详情时页面抖动（布局偏移）

**根因**（用 CDP 探针实测确认，不是猜测）

1. 主因：`ElementDetail.vue` 打开面板时直接 `document.body.style.overflow = 'hidden'`，视口滚动条（本项目 `::-webkit-scrollbar` 固定 10px）消失 → 可视宽度 1404→1414px。周期表是 `grid-template-columns: 36px repeat(18, minmax(0,1fr))`，宽度一变 118 个格子全部重新分配；实测整页横移 9.45px、纵向 3.84px，关闭时再来一次。
2. 次因：异步加载的 `AtomModel3D` 占位块 `.atom-loading` 只有 `aspect-ratio:1/1`，缺 `.stage-wrap` 的 `max-height:46vh`，且 `delay:100` 期间不渲染任何节点 → 面板高度 0 → 504 → 371 变两次，下方「基本信息」被顶动 504px。
3. 3D 组件的按钮条 + 图例高度随视口宽度**和元素**变化（U 有 7 个电子层标签会换行：107 / 136 / 148 / 177px 都有），所以纯 CSS 占位无法 100% 等高。

**修复**
- 新增 `src/composables/useScrollLock.ts`：锁滚动时把滚动条宽度补到 `body.padding-right`（叠加而非覆盖，`window.innerWidth - clientWidth` 为 0 时（macOS 悬浮滚动条）不补偿），带引用计数与实例级幂等保护，卸载自动还原。
- `.atom-loading` 对齐 `.stage-wrap` 尺寸规则（`width:100%` + `aspect-ratio:1/1` + `max-height:46vh`），异步组件 `delay` 100 → 0。
- `ElementDetail` 空闲时 `requestIdleCallback` 预取 3D chunk：chunk 在内存里时替换发生在面板入场首帧（面板还在屏外），无需静态占位即可零跳动。
- 不动 AtomModel3D 内部逻辑（工具栏/图例高度依赖数据，要彻底归零需把 chrome 从异步 chunk 拆出，作为后续可选项）。

**验证**：新增 `scripts/verify-detail-layout.mjs`（`npm run verify:layout`，CDP 探针，与既有 smoke/perf3d 脚本同风格）。dev 与 prod 连续多次：页面位移 0px、占位与舞台等高 0px、面板内容位移 0px、滚动锁定与还原全部 PASS；`npm run smoke` 40/40 通过。

**踩坑**：本机 vite 默认只绑定 `::1`，脚本要 `--host 127.0.0.1`；改代码期间用 HMR 页面测布局会拿到 `useScrollLock is not defined` 的残留状态，探针必须先整页 navigate 再测。
