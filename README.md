# 元素立方 · 交互式元素周期表

一个现代化的元素周期表学习网站，收录全部 118 种元素的详细资料，内置 3D 原子模型与 3D 立方周期表。

## 技术栈

- **Vue 3**（Composition API + `<script setup>`）
- **TypeScript**
- **Vite 8**
- **Three.js**（WebGL，按需异步加载，不影响首屏）

## 功能特性

### 三种视图

| 视图 | 说明 |
| ---- | ---- |
| 周期表 | 标准 18 列布局，含镧系/锕系分栏与族/周期轴标注 |
| 列表 | 按分类分组浏览，移动端默认视图 |
| 3D 立方 | 118 个三维立方体，柱高映射原子半径 / 原子量 / 电负性 / 熔点 / 沸点 / 电离能，可旋转缩放 |

### 检索与筛选

- 搜索：中文名、英文名、元素符号、原子序数、分类名（如「金属」「卤素」）
- 分类筛选：10 种分类多选叠加，非命中元素灰显、命中高亮，实时显示命中数
- 悬停某元素时自动高亮同族与同周期元素

### 元素详情

- 原子序数、原子量、电子排布（上标排版）、各层电子数
- 物理性质（熔点/沸点/密度）、化学性质（电负性/电离能/原子半径）
- 发现历史、简介、主要用途
- 上一/下一元素切换，方向键导航，Esc 关闭

### 3D 原子模型（详情面板内）

- 质子 / 中子核 + 电子层轨道动画，各层按 2n² 容量示意
- **热区交互**：点击原子核或任一电子层弹出信息卡（质子 / 中子 / 质量数、各层电子数与容量、价层标记），点击空白处收起
- **文字标注**：K / L / M… 各电子层与核子数标注，可一键开关
- **缩放**：滚轮 / 双指缩放带上下限 —— 下限保证镜头停在核外不穿模，上限保证原子不缩成一个点；切换元素保留缩放手感，「聚焦原子核 / 重置视角」带平滑过渡
- 视图控制：自动旋转、聚焦原子核、重置视角；支持拖拽旋转、右键 / 双指平移

### 3D 立方周期表

- **点击立方体**弹出元素详情卡：符号 / 名称 / 原子序数 / 相对原子质量 / 电子排布（上标排版）/ 各层电子数 / 族·周期·区、8 项关键性质、主要用途、当前柱高映射数值；资料区可滚动，操作栏固定在卡片底部
- **导航**：卡片内与工具栏的「上一个 / 下一个」按原子序数前后切换，到达 1 号 / 118 号时按钮置灰（不循环）；跳转搜索框输入符号 / 中文名 / 英文名 / 序数自动定位并聚焦相机
- **回到中心**：聚焦元素会移动轨道中心，「⌖ 回到中心 / ⤾ 重置视角」随时把相机平滑拉回周期表整体居中视角
- **标注**：地面族号（1–18）与周期号（1–7）、镧系 / 锕系标记、选中元素悬浮名牌（按相机距离自动缩放），均可一键开关
- 选中元素自动高亮，同周期 / 同族元素联动提亮
- 顶栏搜索 / 分类筛选结果联动：非命中立方体整体压暗
- 视图控制：自动旋转、俯视图

### 体验细节

- **默认暗色主题**，可一键切换浅色；选择记忆到 localStorage，首帧前应用（无闪烁）
  - 恢复「跟随系统」：把 `src/App.vue` 中 `theme.value = readStoredTheme() ?? 'dark'` 改回 `matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'` 即可
- 桌面端与移动端响应式（移动端详情为底部抽屉）
- 快捷键：`/` 聚焦搜索框，`←` `→` 切换相邻元素，`Esc` 关闭面板
- 尊重系统「减少动态效果」偏好；WebGL 不可用时优雅降级，上下文丢失可一键重渲染

## 3D 性能优化

- **图集贴图**：118 个元素的标签合并绘制到单张 2048×1024 画布，每个立方体用 `Texture.clone()` + offset/repeat 采样对应格子；three.js 按 `texture.source` 复用同一份 GPU 纹理，因此 118 个立方体只占 **1 个 WebGLTexture**（原本 118 张 128² 贴图）
- **共享几何体**：118 个立方体共用 1 个 BoxGeometry；原子模型中质子 / 中子 / 电子全部用 InstancedMesh，仅一份球体几何
- **实例化渲染**：核子与电子用 InstancedMesh，单个原子整景约 20 个 draw call、3 万三角面
- **脏检查渲染**：材质高亮仅在选中 / 悬停 / 筛选变化时刷新；柱高动画收敛后停止更新；悬停拾取每帧最多一次射线检测
- **资源释放**：`dispose()` 后强制 `forceContextLoss()`，反复开关面板不会累积 WebGL 上下文；随元素变化的文字贴图随模型销毁，无累积泄漏
- **帧率自适应**：检测到持续掉帧时自动降低渲染分辨率，恢复后逐步升回
- **按需加载**：three.js 仅在进入 3D 视图时异步加载，首屏不被拖慢

## 部署到子路径 `/element-cube/`

站点默认按 **子路径部署**构建（`vite.config.ts` 中 `base: '/element-cube/'`），因此：

- 域名根目录方式访问：`https://<host>/element-cube/`
- 开发服务器同样挂在子路径下：`http://127.0.0.1:5173/element-cube/`（访问 `/` 会自动重定向）

```bash
pnpm build                     # 产物输出到 dist/
# 把 dist/ 整体上传到服务器上的 /element-cube/ 目录（即 index.html 位于 <webroot>/element-cube/index.html）
```

若需改为**根路径**部署，不必改代码，构建时覆盖环境变量即可：

```bash
VITE_BASE=/ pnpm build
```

### Nginx 配置示例

```nginx
location /element-cube/ {
  alias /var/www/element-cube/;   # 指向 dist/ 的内容
  index index.html;
  try_files $uri $uri/ /element-cube/index.html;   # SPA 回退（本项目无前端路由，可省略但建议保留）
}
location = /element-cube {
  return 301 /element-cube/;      # 无尾斜杠统一跳转，避免相对路径解析出错
}
```

> 注意：`alias` 与 `try_files` 混用时最后一项必须是带 `/element-cube/` 前缀的绝对路径；
> 若改用 `root`，则目录结构应为 `/var/www/element-cube/` 且 location 前缀要与物理目录对应。

### 部署自检

```bash
pnpm build
pnpm preview                 # 默认 4173，会自动应用 base
pnpm verify:deploy           # 校验产物在 /element-cube/ 下渲染、无 404、无越界资源请求、3D chunk 正常
```

## 测试

```bash
pnpm smoke   # 交互冒烟测试（需先用远程调试模式启动浏览器，见脚本头部注释）
pnpm shots   # 生成各视图截图到 .screenshots/
pnpm perf    # 3D 性能探针：draw call / 三角面 / 纹理数量与帧率
pnpm verify  # 3D 交互回归：滚轮缩放与上下限、序数导航、边界禁用、回到中心
```

> 测试脚本默认地址 `http://127.0.0.1:5173/element-cube/`，可用 `EC_URL=... node scripts/xxx.mjs` 覆盖（部署校验脚本还支持 `EC_CDP` 指定调试端口）。
